# Remotion Framework Skills - Setup Guide

**Source:** [remotion-dev/remotion](https://www.skills.sh/remotion-dev/remotion) via skills.sh - 47.5K combined installs across 73 indexed listings; first seen 2026-10-30 (morning sweep)

**GitHub:** [remotion-dev/remotion](https://github.com/remotion-dev/remotion) - 69,018 stars, license field reported as NOASSERTION by the GitHub API while `LICENSE.md` carries the two-tier Remotion License, branch main, last pushed 2026-10-30; 88 `SKILL.md` files in three layouts, `packages/skills/skills/<name>/SKILL.md` for the 13 public skills, `.agents/skills/<name>/SKILL.md` for 63 internal contributor skills plus symlinks to the public set, and `packages/codex-plugin/skills/<name>/SKILL.md` for the 12-skill Codex plugin copy

**Category:** Programmatic video production in React, rendering pipelines and media tooling

**Quality Tier:** 🟡 Beta - license field NOASSERTION rather than a standard OSI id; a deep, actively maintained library that covers React video markup, rendering, Studio behaviour and the maintainers' own release and PR workflows

Remotion is a React framework for making videos programmatically: compositions are React components, animations are driven by frame numbers, and rendering happens through a bundled Chromium. This repository is the whole thing, the framework packages, Remotion Studio, the player, Lambda rendering, the documentation site and a large agent skill library that ships alongside the code rather than in a separate docs page.

The skill library is the part this catalog entry indexes, and its shape is unusual. Thirteen public skills live in `packages/skills/skills/` and are published for agents: `remotion-best-practices` is a router that loads the right specialist, and the specialists cover creating a project, React markup, captions, maps, Mediabunny media handling, Studio preview, rendering, upgrades and the commercial licence. Sixty-three further skills live in `.agents/skills/` and are aimed inward, at people maintaining Remotion itself: adding an effect, an element or a package, fixing a Dependabot PR, naming a pull request, shepherding CI, cutting a release. What the install index measures here is a maintainer's daily habits rather than the usefulness of the video skills, which is worth knowing before you read the table as a ranking.

The licensing deserves a sentence up front because it is not an OSI licence. `LICENSE.md` grants free use to individuals, non-profits, and for-profit organizations with up to three employees, and requires a company licence above that size, with the exact terms in the file and at `remotion.dev/license`. Teams evaluating the skills should read that before shipping anything commercial, and the GitHub API reports the licence field as NOASSERTION rather than naming it.

## Installation

The root README does not document a skills install at all. It offers one framework command, `npx create-video@latest`, and links the Agent Skills page at `remotion.dev/docs/ai/skills`. The install path lives in the skills package README, `packages/skills/README.md`:

```bash
npx skills add remotion-dev/skills
```

```bash
gh skill install remotion-dev/skills
```

Both commands name `remotion-dev/skills`, a separate repository rather than this monorepo, and `packages/skills/README.md` is generated by `packages/skills/scripts/sync-readme.ts`. The local package directory is therefore the source of truth for the thirteen. The skills README also notes that a new project is offered the option to add skills at creation time, which is a different creator command from the root README's own `npx create-video@latest`:

```bash
bun create video
```

Framework-side commands appear inside the skills themselves rather than in a README, and they are what the agent will actually run once installed: `npx create-video@latest --yes --blank --no-tailwind my-video` to scaffold, `npx remotion render` and `npx remotion still` to export, `npx remotion add @remotion/media` to add a package, and `npx remotion upgrade` to move a project and its local skills forward.

Hermes is not a target this repository publishes an adapter for, so the durable route for this profile is a directory copy from a clone:

```bash
cp -R packages/skills/skills/remotion-markup \
  ~/.hermes/profiles/corpusiq/skills/remotion-markup
```

Copy the whole directory, not the markdown file. `remotion-markup` carries 33 sibling reference files (`compositions.md`, `timing.md`, `transitions.md`, `voiceover.md`, `3d.md`, `lottie.md` and more), `remotion-captions` carries `transcribe-captions.md`, `display-captions.md` and `import-srt-captions.md`, and `remotion-best-practices` nests the other public skills under itself. A lone `SKILL.md` leaves the agent pointing at relative links it cannot open.

## Why This Matters for Hermes Agents

Video is the one media type an agent usually cannot produce end to end, and Remotion changes that shape: the output is code, the preview is a browser, and the render is a command. The public skills encode the decisions that make such a project work on the first attempt, from scaffolding rules (empty folder versus subfolder, `create-video` refusing non-empty directories) to the instruction that Studio should be opened before any composition is written so the user can steer the result while it is being built.

The router design is the other reason this suite installs well. `remotion-best-practices` is deliberately thin: it decides whether the request is creation, markup, maps, multimedia, interactivity or preview, loads the matching skill, and it tells the agent not to render by default when the user asked to make a video, because an interactive preview is what they actually want. A Hermes profile can hold that single skill and still reach the rest if the directories are present, instead of loading a dozen descriptions into routing context on every turn.

For builders the useful part is the reference depth behind the names. `remotion-markup` is not an essay, it is a folder of around forty topic files, one per decision: compositions, timing, transitions, audio, fonts, lottie, 3d, motion blur, measuring text, multi-scene structure. The agent reads the file that matches the question instead of carrying the whole framework in context, which is exactly how a long video project stays inside a token budget.

The internal half is unusually honest documentation of how a video framework is maintained, and it transfers. The workflow behind adding an effect to `@remotion/effects` touches implementation, exports, docs, demos, preview images and the skill text itself, and that checklist is a template any team shipping an animation package can borrow.

Finally, the suite is explicit about what needs a live service, so a Hermes cron can plan around it: `vercel` needs a deployment to watch, `upload-r2` and `offload-r2` need a Cloudflare bucket behind `remotion.media`, `update-chrome-binaries-test-region` needs Lambda publishing rights in eu-central-1, and the issue, flake and PR skills need an authenticated `gh` session.

## Usage

| You say | What happens |
|---|---|
| "Make a promo video for a record store" | `remotion-best-practices` routes to `remotion-create`, which scaffolds with `npx create-video@latest --yes --blank --no-tailwind`, installs dependencies, opens Studio for preview, and then builds the composition from `remotion-markup` guidance rather than rendering straight away. |
| "Animate a route from Los Angeles to New York with the camera following it" | `remotion-maps` takes the request: static map setup, animated route and markers, Mapbox or MapLibre or MapTiler configuration, GeoJSON input, and an optional CesiumJS flyover if the shot needs 3D. |
| "Add captions from this SRT and animate them word by word" | `remotion-captions` loads the `Caption` type contract, imports the SRT through `import-srt-captions.md`, then uses `display-captions.md` for the rendering pattern and hands follow-up work back to the router skill. |
| "Render frames 0, 30 and 90 as PNGs to check the layout" | `remotion-render` uses `npx remotion render [composition-id] out/frames --frames=0,30,90 --image-format=png`, or `npx remotion still [composition-id] --scale=0.25 --frame=30` when a single still is enough. |
| "Upgrade this project to the latest Remotion and keep the skills in step" | `remotion-upgrade` inspects manifests and the lockfile, runs `npx remotion upgrade`, aligns `@mediabunny` and auxiliary packages with the target `@remotion/studio` dependencies, then updates the installed skills in the same pass. |
| "I am adding a new sound effect to the sound-effect library" | `add-sfx` walks the addition of a new sound effect to `@remotion/sfx`, and the neighbouring internal skills cover package registration, docs and demos when the change grows beyond one folder. |
| "Which skills does this repo actually ship, and where do they live?" | `skill-locations` states the placement rule: public redistributable skills under `packages/skills/skills`, internal agent-only skills under `.agents/skills`, symlinks between them, and `bun run syncskills` plus `bun run checkskills` to keep them in step. |

```bash
  https://raw.githubusercontent.com/remotion-dev/remotion/main/packages/skills/skills/remotion-best-practices/SKILL.md
```

Expect `200` three times. Read at least the router before installing: its whole value is the routing table, and a copy whose relative links were broken in transit will still pass `head` and fail the agent. After a directory lands in the profile, confirm the frontmatter and the shape of the copy:

```bash
head -6 ~/.hermes/profiles/corpusiq/skills/remotion-create/SKILL.md
ls ~/.hermes/profiles/corpusiq/skills/remotion-markup | wc -l
```

A good copy shows `name:`, `description:` and `version:` in the frontmatter, and the second command should report a directory of reference files rather than a count of one. If it returns one, only the markdown was copied.

Do not read that as a blanket clearance: the sample covers the top of the install table, and the skills that matter most for a builder, `remotion-markup`, `remotion-render` and `remotion-captions`, are not in it.

The real review surface is what the installed skills instruct an agent to run. Rendering downloads a Chromium build and executes the project's code in it, `npx create-video@latest` pulls a scaffold from npm, and the internal skills run `gh`, `bun` and Vercel and Cloudflare tooling against real accounts. Installation does not grant any of that, but the instructions will ask for it, so keep credentials in the environment rather than in a prompt and scope any token that the agent can reach.

One licence point belongs here as well: `LICENSE.md` is a two-tier licence, not MIT, and the free tier stops at for-profit organizations with more than three employees. The GitHub API reports NOASSERTION because the file is not a standard OSI text.

## Limitations

- Snapshot data, verified 2026-10-30: 47,489 combined installs across 73 indexed listings; 69,018 GitHub stars; license field NOASSERTION in the GitHub API with a two-tier Remotion License in `LICENSE.md`; last pushed 2026-10-30. Counts drift over time.
- The index and the tree do not line up. Four indexed listings have no directory in the current checkout: `make-pr`, `update-remotion-rust-ffmpeg`, `install-canvas-capture-browser` and `publish-element`. Going the other way, the tree carries skills the index does not rank, among them `remotion-license`, `remotion-maps`, `remotion-multimedia`, `remotion-studio`, `remotion-upgrade`, `product-recording` and `update-ffmpeg`.
- Install counts here measure maintainer habits, not usefulness. The top of the table is internal contributor work such as `web-renderer-test`, `writing-docs` and `video-report`, while the public video skills sit in the tail, `remotion-create`, `remotion-render` and `remotion-captions` at 107, 110 and 104 installs. Judge a skill by its `SKILL.md` and its reference folder.
- The skills are instructions, not a runtime. Nothing renders without Node, a Remotion project and the CLI downloading its own browser, and several skills are inert without a live service: `vercel` needs a deployment to watch, `upload-r2` and `offload-r2` need a Cloudflare R2 bucket, `update-chrome-binaries-test-region` needs Lambda publishing in eu-central-1, and the issue, flake and PR skills need an authenticated `gh`.
- The published install commands name `remotion-dev/skills`, a separate listing, not this repository. The copies under `packages/skills/skills/` are the source, and `packages/skills/README.md` is generated, so treat the package directory as authoritative and the readme as a view of it.
- A large share of the indexed names are Remotion's own release and repository housekeeping, `release`, `update-version`, `update-stars`, `upgrade-caniuse` and their neighbours, and they will do nothing useful in a project that is not the Remotion monorepo.

## Pro Tips

- Install `remotion-best-practices` and `remotion-markup` first. The router costs one description in context and reaches the rest, and the markup folder answers most of the questions an agent actually gets asked about a video.
- Copy directories, not files. The value of `remotion-markup` is its 33 reference files, and a markdown-only copy turns a precise lookup into a confident guess.
- Keep the agent in preview mode while it works. Every public skill repeats the instruction to open Studio before writing a composition and not to render unless the user asked for a file, which is also the cheapest way to review a video change.
- Check the licence before the first commercial render. The free tier covers individuals and companies up to three employees, and a team that crosses that line needs the company licence, not a code review.
- Pin the version. The public skills carry `version: 4.0.539`, and `remotion-upgrade` exists precisely because a project and its installed skills drift apart quickly.
