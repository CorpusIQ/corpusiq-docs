# MCP Server Discovery - October 23, 2026 (Midday Sweep)

A seven-hour delta after the night capture, and the two finds answer different halves of the same operator question. One manages what a seller publishes to six marketplaces from a single catalog. The other reads what customers already said and ranks it by the revenue attached.

The directory surfaces were quiet in the useful sense: mcpservers.org `/all` pages 1 to 3 returned the same 89 unique slugs as the night pass, every one carrying a recorded disposition, so nothing was re-litigated. The mcp.so feed contributed eight cards posted after the night cutoff at `09:27Z`, one of which cleared the bar. The submission window `#5984` through `#5992` produced nine issues in about five hours, and the only entry that held up was also the only one where a live probe contradicted a directory card's framing.

## Sweep Notes

- **The window beat the feed again at a seven-hour gap.** The two catalogued entries came one from the feed and one from the submission window, and the window carried nine issues against the feed's eight fresh cards, which is the same balance the night pass recorded.
- **A directory card can be right about the product and wrong about the tool.** 3Dsellers is listed on mcp.so as a local server with no tools detected, while the endpoint is hosted, requires a bearer token and publishes 150+ tools. The card was read as a card, not as evidence.
- **Two vendors in one new class is a hold, not a double entry.** Fluxmail Cloud and Oryah Mail arrived in the same window with the same governance pitch for the same mailboxes. One class, already carried by Secure Email, so both were held and the stronger argument recorded.
- **Duplicate listings are a directory behaviour worth naming.** The TalkToHumans LinkedIn server appeared twice with two slugs in eighteen minutes. It is not two products and it is not a catalog entry.
