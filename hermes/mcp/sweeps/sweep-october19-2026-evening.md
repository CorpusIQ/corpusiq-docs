# MCP Server Discovery - October 19, 2026 (Evening Sweep)

Evening delta about eight and a half hours after the October 19 midday capture. Both directories rotated hard in that window: the mcp.so `/feed` page 1 produced six cards posted after the midday pull and none of them cleared the bar, while mcpservers.org `/all` pages 1-4 served 120 cards, 99 of them not named anywhere in the midday sweep or the night sweep before it. One entry was catalogued, and it is the first entry this catalog has added in the agent-governance class since August: a pre-action mandate gate whose job is to refuse a payment that has quietly left the authority it was granted.

The verification on this one produced a finding worth writing down. The hosted server is live and every one of its six rules was fired deliberately against it. Its own README, though, tells you to `pip install drift`, and the `drift` package on PyPI belongs to an unrelated CMS content editor that last published version 0.0.7 from a Bitbucket repository. Following the install instructions installs a different library. That is recorded in the guide rather than glossed over, because an install command that silently fetches the wrong package is exactly the kind of thing that gets blamed on the agent later.

## New Servers Catalogued

| Server | Category | What it does |
|---|---|---|
| [drift MCP](/hermes/mcp/servers/external/drift-mcp/) | Compliance / Agent Governance | Apache-2.0 MCP server (`github.com/mrpkk/drift`, default branch `master`, created October 4, 2026, last push October 20, 2026, zero stars and forks, Python 3.11+, `dependencies = []`) hosted at `https://drift.rta.lat/mcp` speaking Streamable HTTP, protocol 2025-06-18, server info `drift 0.1.0`, no auth. Three tools, all annotated read-only, idempotent and non-open-world: `drift_check` (one action against one mandate), `drift_session` (a list of actions, per-action verdicts plus a chain fingerprint) and `drift_explain` (the rules in order, with reasons). The gap it fills is precise: AP2 verifies a payment mandate once, at signature time, and after that nothing holds the agent inside it. drift re-checks six rules in a fixed order before every action - `amount`, `payee`, `audience`, `currency`, `window`, `intent` - default DENY, with the refusal naming the most important rule rather than an incidental one. The mandate is a frozen dataclass (an edit makes a new mandate, it cannot widen the signed one), window bounds are inclusive, amounts are integer minor units, and a session's fingerprint breaks if any earlier decision is rewritten or reordered. Verified live, one probe per rule: within-limit action ALLOW with fingerprint `67e0bbb428d77670`; 99999 against a 10000 cap DENY `amount`; wrong payee DENY `payee`; audience swapped to `attacker.example` DENY `audience`; EUR against USD DENY `currency`; action past `valid_until` DENY `window`; `wire_all` against `["buy"]` DENY `intent`; and a three-action batch returned `{submitted: 3, allowed: 1, denied: 2, breach_by_rule: {"amount": 1, "payee": 1}}`. One footgun found and documented: an empty `allowed_intents` disables the intent rule - a mandate with `[]` returned ALLOW for an intent named `transfer_everything`, which the spec treats as an explicit "any intent" decision. Stated limits, from the vendor: it does not verify signatures (AP2 does), does not execute, keeps no state, and `intent` arrives from the agent as untrusted input; proving what actually happened is the same author's `attest`. Pricing: hosted free tier 100 checks a day, above that x402 per call on Base; self-hosting free, optionally via the included `Dockerfile` or `windmill_script.py`. **Install trap, verified:** PyPI `drift` is an unrelated CMS package at 0.0.7 and `drift-mcp` does not exist (404), so `pip install -e .` from a clone is the working path. |

**One pattern worth recording for next time:** four of the last six mcpservers.org cards in this capture follow the same shape - a remote MCP server whose only tools describe the vendor's own product and run its calculator. Recoup, Winback HQ and two others in the page-2 cohort are built this way deliberately, because a listing on an MCP directory is now an acquisition channel. It is a legitimate use of the protocol and a poor reason to catalogue something, so the disposition rule is: if the tool reads no customer data and answers only questions about itself, it is a sales surface and it is held.
